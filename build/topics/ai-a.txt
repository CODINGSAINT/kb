## 1. Parameter answer and chosen request policy

Temperature changes sampling from token scores; top-p limits a cumulative-probability candidate set where supported. Neither establishes truth. ## 2. Bounded request contract

```text
ModelRequest: modelVersion,messages,outputCap,sampling,responseSchema,deadline
Outcome: COMPLETE | TRUNCATED | CONTRACT_FAILURE | THROTTLED | TIMEOUT
Usage: actual input/output and provider-specific usage categories
Cost = (inputTokens*inputPrice + outputTokens*outputPrice)/1000000
```

At 2,000 input and 500 output tokens, I calculate using current configured prices rather than hard-coded marketing estimates. At 100 requests/s lasting eight seconds, average in-flight work is roughly 800, so a bounded executor/queue matters independently of token caps.

A truncation finish reason means the requested object may be incomplete; I do not deserialize partial text as a successful business result. A 429 receives bounded backoff within the original deadline. One layer owns retries to avoid multiplication. After a tool effect, a whole-run retry must reuse or reconcile the operation identity. ## Requirements

## 1. Complete embedding answer and selected design

An embedding maps text into a fixed-length vector learned by a model. Related meanings can be close under the configured metric, making paraphrases retrievable without exact keyword overlap. I choose one compatible embedding model for documents and queries, versioned chunks and authorization-filtered nearest-neighbour retrieval.

## 2. Similarity and retrieval algorithm

```text
cosine(a,b) = dot(a,b)/(norm(a)*norm(b))
For (1,0) and (1,1): 1/sqrt(2) = approximately 0.707
Pipeline: authorized document -> chunks -> embed -> index
          authorized query -> embed -> scoped top-k -> rerank -> evidence
```

Zero norms and mismatched dimensions are rejected rather than silently scored. Ten million 768-dimensional float32 vectors occupy 30.72 GB raw; indexes, text, metadata and replicas add cost. Approximate search trades exact recall for resource efficiency, so I measure recall@k against known relevant chunk IDs.

For “recover access,” a password-reset passage can match semantically. For error code E1042, I also retrieve lexically and fuse/rerank candidates under a defined method; unlike raw scores are not blindly added. Model replacement builds a new index and switches query embedding plus index together. Current source permissions apply before forbidden content reaches a model. Deletion retires chunk IDs/cached evidence, and source revision IDs let the answer cite inspectable text rather than an opaque vector.

### Calculate similarity and storage

For vectors `(1,0)` and `(1,1)`, cosine similarity is `1/(1×sqrt(2)) ≈ 0.707`. A zero vector has no defined cosine direction; handle it explicitly. Mismatched dimensions are an input error, not a score of zero.

Ten million 768-dimensional float32 vectors require `10,000,000×768×4 = 30.72 GB` raw numeric storage, before metadata, text, index edges, replicas and headroom. Approximate nearest-neighbour search trades exact recall for speed/memory; measure retrieval quality on your corpus.

### Mechanism and rationale

**Design question:** Why should a search for "password recovery" find a document titled "reset credentials", and when should it not?

An embedding model maps text to vectors in its learned space. Compare query and document vectors produced by compatible model/preprocessing versions. Cosine similarity compares angle; dot product and Euclidean distance have different normalization assumptions. Nearest neighbors are candidates for relevance, not verified answers.

### Mechanism and rationale

**Design question:** What does Spring AI provide, and what still belongs to the application?

Spring AI integrates model clients, embeddings, vector stores, tools and advisors with dependency injection and auto-configuration. The framework reduces integration boilerplate; it does not supply product authorization, tenant isolation, business invariants or an evaluation dataset. Provider portability is partial because capabilities differ.

### Architecture and contracts

```text
HTTP input -> authenticated application service -> ChatClient/EmbeddingModel -> provider adapter -> validated domain result -> response
```

### Worked reasoning and capacity example

At 100 requests/s and 3 seconds average provider residence time, Little’s Law suggests about 300 in-flight calls. A large thread pool cannot create provider quota or database capacity; bound concurrency and queue time.

## 1. Chosen response strategy

For a short explanation I use blocking content; for long prose I return a bounded stream; for application decisions I use a typed result plus validation. ChatClient is a builder/consumer API over ChatModel, not storage or business authority. I retain metadata when usage or finish evidence matters.

## 2. Concrete consumption choices

## 5. Detailed decisions, algorithms and failure behaviour

### Mechanism and rationale

**Design question:** How do you use ChatClient without losing provider metadata or mixing users’ request state?

ChatClient creates a fluent request over a ChatModel. A completed call can yield text, a typed entity or a ChatResponse containing metadata. A stream returns pieces over time; these are not necessarily words, sentences or complete JSON documents.

### Architecture and contracts

```text
Fresh request spec -> task/system message -> user/evidence messages -> advisors -> call or stream -> metadata and validation -> response

Application contracts (design outline):
ClientFacade.answer(question,conversationKey); CompletionEnvelope(answer,usage,finishReason,promptVersion)
```

Build ChatClient once from the injected builder, then create a new prompt specification for each call. A request-specific conversation ID belongs in advisor parameters after authorization.

### Worked reasoning and capacity example

If 500 output tokens arrive at an illustrative 50 tokens/s after a 1-second prefill, completion takes about 11 seconds. Streaming can show the first piece earlier but cannot make all 500 tokens arrive at once.

### Java and Spring AI implementation outline

```java
reactor.core.publisher.Flux<String> stream = client.prompt()
    .user(question).stream().content();
// Propagate cancellation and bound provider concurrency in the application.
```

### Design decisions and alternatives

Use content() for a simple demonstration, chatResponse() when usage/finish metadata matters, and entity mapping only when the result contract can be validated. Keep streaming text and finalized structured objects as different response modes.

### Failure scenario and safe recovery

A browser disconnects while the model continues generating. Propagate cancellation and bound server work. If a stream ends halfway through a JSON object, do not persist it as a valid final answer.

### Security, privacy and provenance

Logging a fluent request or response can expose user prompts, retrieved documents and secrets. Log IDs, versions, counts and redacted diagnostics by default.


**Verification criteria:** Test cross-user request isolation, stream termination, empty responses, provider truncation and usage extraction. Measure successful task cost rather than only request count.

### Trace a stream completely

If chunks are `"Trans"`, `"action"`, `"s..."`, they are transport pieces, not necessarily whole words or sentences. Append in order and handle partial output. Do not expose a partial generated command as an executable action. Structured documents usually need full parsing/validation before business use.

Record time to first token and time to completion separately. A two-second first token followed by a minute-long response is a different experience from a ten-second response delivered all at once. Streaming changes delivery latency, not necessarily total token cost or factual quality.

I select one response consumption per model request: text, a response object with metadata, a stream or a converted DTO. Streaming changes delivery timing, not factual reliability. Cancellation, truncation and validation decide whether the application records a complete answer.
