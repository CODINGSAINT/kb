A likely token can still be wrong

Change a fictional next-token distribution and its temperature. Inspect the probabilities, then draw independent samples from this one fixed prefix.

Every number is made up. This is a three-token sampler, not a live LLM or a model-quality evaluation. Nothing is sent to a provider.

The question and the source stay fixed

Question: Does HashSet guarantee insertion order?

Source answer: NO. The Java 21 HashSet contract does not promise iteration order. A token's sampling probability cannot change this contract.

1. Choose a toy distribution

The vocabulary order is NO, YES, UNSURE. These names stand for three fictional token IDs. We choose the scores; they were not measured from a model.

0: greedy1: original2: flatter

Use arrow keys to change the value. At positive T, scale logits and normalize. Here, T = 0 selects the first highest-scoring token; real APIs have their own contracts.

z = ln(base probability)
pᵢ(T) = exp(zᵢ/T) / Σ exp(zⱼ/T)

NO leads, matching the source for this toy question. This does not mean every sampled token will match.

3. Draw from this same prefix

No samples drawn. Source answer remains NO.

Each click samples the same distribution independently using browser randomness. A real generator appends a token and recomputes scores for the changed prefix. Changing a control clears the old counts so different distributions are not mixed.

What the changes show

  1. At T = 1, the first fixture gives NO 60%, YES 30% and UNSURE 10%. Sampling can choose YES despite NO leading.
  2. At T = 0.5, the first fixture gives about 78.2609%, 19.5652% and 2.1739%. The squared values are divided by their sum, 0.46.
  3. Choose “YES leads” and lower T. The wrong answer becomes more likely; T = 0 chooses it every time.
  4. The NO-leading and YES-leading fixtures have equal entropy at the same T. Swapping probability mass changes the answer, not the spread.

The application must retrieve permitted, current evidence and handle unsupported answers. Temperature is a sampling control, not an evidence source. Top-k, top-p and provider behaviour are outside this toy.
