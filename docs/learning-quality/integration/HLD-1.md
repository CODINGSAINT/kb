## Decisions and material limits

- Eight-character random Base62 with a unique durable insert and bounded collision retry. Immutable destination/expiry; no code reuse after expiry/revoke. Public codes are not authorization.
- Owner/request-ID fingerprint and original result retained 24 hours. Replay occurs before future-expiry validation, so a retry cannot accidentally create/revive an expired link.
- 30-second server-cache lease begins at the authority read, not the PUT; copies preserve deadline. Expiry can shorten it. The chosen policy deliberately permits a stale redirect after revoke but within the original lease. Invalidation and versions alone are not claimed as instant revocation.
- A real deployment must provide fresh authority reads, durability/failover fencing and a monitored clock-error budget. The model's one clock/local synchronization does not prove those properties.
- HTTP 302/no-store policy does not recall previous browser-cached or already issued redirects. The walkthrough models server cache state only.
- Analytics is explicitly best effort; stable event IDs and dedup remove delivery repeats, not pre-publication loss or repeat visits. Independent database shards require a new transaction/coordinator design.
