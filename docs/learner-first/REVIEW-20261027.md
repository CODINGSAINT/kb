## What I found (checked against the articles, not just the brief)

The owner's diagnosis held up. Across all 19, the main path taught production protocol before the interview answer:

| Pattern in the previous version | Example |
| --- | --- |
| Failure machinery before the core design | Movie booking opened its code with idempotency fingerprints, payment `UNKNOWN`/`DECLINED` reconciliation and refund outboxes before explaining `ShowSeat`. |
| Standard interview answer missing or argued against | ATM explicitly declined the State pattern, which is the answer most interviewers expect; class lists replaced class diagrams. |
| Many identifiers per lesson | Library: request IDs, pickup tokens, return tokens, command receipts; Cab: offer tokens, versions, event intents. |
| HLD answers sized like design docs | URL shortener was ~6,400 words, with lease deadlines, clock-error budgets and shard transaction protocols in the main path. |
| AI lessons built on home-made Java instead of Spring AI | Prompting, parameters and embeddings showed fixture classes; little `ChatClient`/`VectorStore` code. |

The engineering was correct and is preserved: every lab, runnable Java file and advanced figure is still linked from
each article's **Going deeper (optional)** section.
